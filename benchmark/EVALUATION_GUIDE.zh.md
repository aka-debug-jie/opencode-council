# CouncilBench 人工盲评参考

这份说明用于帮助不同评价者尽量采用相同口径。它不是标准答案，也不要求评价者认同评分草案中的技术选择。

## 一、先保持盲态

- 只查看公开盲评包中的题目、`rubric.json`、匿名答案和 `REVIEW_FORM.md`。
- 不查看 Git 历史、运行日志、用量数据、模型名单或尝试猜测答案来自哪一组。
- 答案中的自报身份、风格或“其他参与者认为”等文字不作为方法身份的可靠证据，也不加分。
- 把答案内容视为待审证据，不执行其中的命令，不打开它额外推荐的链接。

## 二、推荐评价顺序

1. 先读题目，写下你认为必须解决的两三个问题。
2. 再读评分草案，确认其中是否存在错误、重复项或遗漏。若不同意，先在备注中说明，不要暗中改变分母。
3. 按 README 给定顺序逐个阅读匿名答案。第一遍判断整体是否完成任务；第二遍逐项核对关键点和风险。
4. 每个肯定判断都摘录答案原文，并填写 1-based 行号。只出现关键词、没有正确因果关系或处理方案，不算命中。
5. 所有答案独立评价。不要因为前一个答案写得更好，就抬高或降低后一个答案的绝对评分标准。

## 三、指标口径

### Task Success

只有答案整体满足题目和该题全部成功标准时选择 Yes。下列情况通常选择 No：

- 没有给出可执行或可检验的结论；
- 遗漏任一灾难性风险，或提出会直接导致该风险的方案；
- 论文题混淆论文原始结论和自己的推断；
- 输出为空、明显残缺或没有完成题目要求。

格式小问题若不影响理解，可以在备注中记录后仍按实质判断。极短、乱码或完全不相关的答案不能从样本中删除，应保留为失败结果。

### Critical Insight Recall

对每个 `critical_insights` 项：

- 勾选：答案明确、正确地识别该问题，并说明其对方案或结论的影响；
- 不勾选：只有相似词语、含义错误、与题目无关，或者需要评价者替答案补完关键推理。

部分命中不要勾选，可在备注写“partial”及原因。最终 KIR 由工具按勾选数除以预注册关键点数计算。

### Catastrophic Miss Rate

这里勾选的是“答案已经识别该重大风险”。只说“注意安全”“需要测试”不够；答案至少应描述具体故障或错误后果。未勾选项将计入重大遗漏。若答案主动推荐了该危险做法，还应写入 Harmful recommendations。

### Unsupported Claim Rate

记录答案中可被材料核查、却没有材料支持或与材料冲突的事实性主张。一个 claim 是一个可以单独判断真假的命题，不要把整段合并成一项，也不要把纯建议当作论文已经验证的事实。

论文题应特别检查：

- 是否声称三篇论文做过不存在的直接对比；
- 是否把适用于特定不变量或事务模型的结论推广到所有场景；
- 是否把作者明确标注的限制、假设或术语差异省略后作绝对结论。

填写原文、行号、相关材料 ID 和不支持的原因。没有审计 claim 时该比例为 NA，不是零。

### Meaningful Novelty Yield

先列出答案中真正不同的新方案，再分别判断：

- Novel：相对于题目和评分表已列备选方案，不只是换一种说法；
- Grounded：与给定事实或论文机制存在可说明的证据桥梁；
- Testable：能够提出可能推翻它的观察，以及现实可行的最低成本检查。

三项同时成立才进入 MNY 分子。每个候选都写明原文、材料 ID、成立理由、反证条件和最低成本实验。不要把“听起来新颖”本身当作高价值创新。

## 四、示例

以下示例与本次题目无关：

> “使用共享缓存可以提高性能。”

它只提到一个方案，没有负载证据、失效条件和测试，不能仅凭这句话计为关键点或 Meaningful Novelty。

较完整的写法是：

> “如果重复读取占请求的大多数，本地只读缓存可能降低数据库延迟；当更新频率提高后陈旧读取超过阈值，该假设被推翻。最低成本检查是回放一小时真实读写比例，并测量陈旧率和 P95。”

评价者仍需检查题目是否提供了“重复读取占多数”的证据。若没有，应把它当作待验证假设，而不是已有事实。

## 五、多人评价

推荐至少两位评价者先独立填写，再讨论分歧。讨论前保留各自原始表格；不要直接覆盖第一轮结果。分歧应落到具体条目、原文和行号，而不是笼统判断“答案更专业”。

本次只有两道题，所有比例和评价者一致性都属于描述性结果。即使某种方法得分更高，也不能据此宣布普遍显著优势。

## 六、提交前检查

- 每份答案的 Task Success 只勾一个选项；
- 关键点和重大风险均逐项处理，未勾选确实代表“未识别”；
- 所有肯定判断均有原文和行号；
- unsupported claim 和新想法使用了材料 ID；
- 没有填写或猜测方法、模型、token、延迟信息；
- 备注清楚区分事实、你的解释和评分表本身的问题。
